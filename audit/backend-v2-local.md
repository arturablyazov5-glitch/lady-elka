# Backend v2 — локальный автономный scaffold, 03.10.2026

`productionReady=false`. Созданы только `local-backend-v2/**` и этот отчёт. Прототип не является опубликованным endpoint и не подключён к checkout. Существующие pay, migrations, frontend, конфигурация и dirty work не изменялись этим этапом. Никаких remote requests/writes, secrets, deploy, install, Docker/Supabase runtime, bank/Telegram, commit/push.

## Реализовано

- `local-backend-v2/router.mjs`: явные create/status/callback/internal-retry, injected auth/provider/notifier/store/validator. Неизвестный route 404. Status возвращает только version/endpoint/id/status после ownership auth; неизвестный и чужой ID одинаково 404. Строка service_role не является auth/isolation.
- `contract-adapter.mjs` читает готовые exports `storefront/api-v2/contract.mjs`, проверяет version/endpoint, полный canonical fingerprint включает business payload и identity. Trusted quote обязан подтвердить catalog revision/freshness и сумму в minor units. Catalog transport не реализован. Ошибка shared contract сохраняет HTTP status; каталожная неопределённость fail closed.
- Исходный storefront orderId сохраняется. Отдельный bank orderNumber `LE2` + 28 hex = 31 символ, randomBytes, UNIQUE, без truncation. Legacy pending не переименовывается и не импортируется. Реальный provider limit/merchant-wide collision ownership ещё не подтверждены.
- `schema-draft.sql` находится вне migration directories. Только le_checkout_v2 orders/bank_queue/effects/admission_reservations/budgets; explicit search_path/qualified references, PUBLIC revoked. Нет grants, roles, cron, extension installation или legacy RPC/table references. Reserve + admission — единая транзакция; exact replay не потребляет admission повторно, conflicting fingerprint 409. Закрытие create не блокирует повтор существующего заказа/status/callback/retry.
- Effect claims атомарны, новые/доказанно not_sent failed могут запускаться в пределах configured bank/telegram budgets. running/unknown/succeeded не освобождаются по TTL и не повторяются. Исключение provider, неоднозначный ответ или ошибка bind дают unknown. SQL bind — transaction orders+queue; callback recovery — transaction own order+queue. Неопределённые внешние effects требуют отдельной ручной процедуры, которой здесь нет.
- Callback не доверяет callback amount/status: auth затем exact persisted payment mapping, actual provider evidence verified=true + paid + exact paymentId/bankNumber/amount. Чужой namespace не получает эффектов. Notification использует immutable snapshot максимум 20 recipients, отдельные per-recipient claims. Internal retry максимум 20 orders за проход; отсутствуют scheduler и worker loop.

## Проверено локально

`node --test local-backend-v2/tests/router.test.mjs`: **8 tests passed**. Использован уже установленный PGlite, синтетические auth/catalog/bank/notifier, без network transport. Проверены 12 concurrent exact replays → 1 bank registration; changed payload → 409; чужой status/service_role denied; foreign callback → 0 notifications; mismatch actual evidence denied; matching paid callback + replay → 1 notification; missing schema/recipients/provider fail closed; unknown/running block retry; atomic admission capacity 1 допускает ровно один из трёх orders; closed create permits exact existing recovery; exhausted/missing effect budget → 0 bank requests; 1000 unique LE2 IDs ≤32; shared contract identity/catalog/full fingerprint. Sentinel public.payment_orders/public.le_orders остаются неизменными. SQL containment проверяется отдельно.

PGlite исполняет draft SQL и проверки транзакций в одном локальном процессе. Это **не доказательство production distributed quotas**, реальных PostgreSQL/PostgREST roles/grants, Edge concurrency или multi-process crash recovery. Tests используют минимальный injected synthetic validator для сценариев router и отдельно проверяют мост к реальному shared pure contract; второго business validation engine нет.

## Блокеры активации и пределы

- `router.mjs`, provider.register/evidence/notifier.send: только adapter interfaces, никаких настоящих transports, verified evidence/authenticity, bank callback topology или merchant/bot quota coordination с legacy. При uncertain evidence оплата не подтверждается. Claims сами по себе не доказывают реальную доставку.
- `contract-adapter.mjs`, verifyCatalog: production data/revision/freshness отсутствуют; текущий offline snapshot нельзя использовать как fresh.
- `store.mjs`: local SQL executor adapter; нет restricted-role PostgREST/profile adapter, schema exposure, deployment configuration. Будущая server role требует отдельного review; service_role в shared project не обеспечивает isolation. SQL ownership опирается на trusted router caller identity, не на grant существующей production роли.
- `schema-draft.sql`, budgets: finite counters только конфигурируемые локальные окна; нет replenishment/window lifecycle, распределённого request/status/replay/auth/invalid callback rate limiting, общего provider budget с legacy, bound worker wall time или production quota values. Нельзя трактовать этот scaffold как готовую abuse protection.
- Callback без persisted mapping fail closed. Unknown bank registration до bind остаётся pending_review и не восстанавливается callback по одному bank number. Нет автоматического импорта/повтора; нужна отдельная доказанная manual recovery процедура. Background provider polling также не реализован.
- Полный provider effect результат/redirect URL не является частью текущего чистого status contract; adapter хранит payment mapping, но production card redirect flow ещё не реализован. Валидатор/shared contract не менялись.

Будущий rollout требует отдельного разрешения и проверки всех блокеров. Rollback: закрыть новые create, сохранить status/completion только своих принятых orders; сохранить unknown/running для review, не направлять их в legacy и не удалять queues. Никаких production schema/grants/cron изменений этим draft не предлагается применять автоматически.
