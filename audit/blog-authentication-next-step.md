## Практический маршрут без новой публикации и без выдачи токена

Подготовлен integration-qa/blog-auth-readiness/authorized-console.js: единственный вставляемый блок, собранный из существующего runner.mjs (с удалением только export у функции) и admin-ui-snippet.js. Код НЕ исполнялся. Он не требует установки или размещения скрипта на сайте и выполняется только в console уже авторизованной Pages-вкладки. Файл содержит явное предупреждение о будущих реальных мутациях. Не отключать браузерные предупреждения о вставке/безопасности, не использовать чужой origin. Использование DevTools console — временный acceptance adapter, не штатный blog UI.

При выполнении следующего задания оператор открывает console в той же вкладке и вставляет весь файл. Его origin/path guard разрешает только https://arturablyazov5-glitch.github.io/lady-elka/ или index.html. Request adapter берёт имеющуюся сессию внутри closure и отправляет её только в https://mgnotvaahftrbifqtahf.supabase.co/functions/v1/le-admin-blog; runner получает лишь transport, а не credential. Так же использует сессию canonical app/public/js/blog.js. Cookies omitted; /published идёт без Authorization. Никакого token dump, HAR, credential аргумента в shell/URL или вывода ответов других статей не требуется.

Сценарий сначала GET /posts: 401/403/CORS/отсутствие session останавливают нормальный запуск до POST. Затем создаётся уникальный qa-blog-live-UUID со status=draft, пустой обложкой и только synthetic text. Независимый GET подтверждает id/text/revision. Draft проверяется на отсутствие в /published и /export. PUT меняет только synthetic text с optimistic revision, отдельный GET подтверждает сохранение. Finally подтверждает собственные slug/title/id/status/revision, DELETE удаляет именно QA draft, повторный GET проверяет отсутствие. Список/содержимое чужих статей не включаются в итоговый JSON.

Успех требует одновременно mode=live, passed=true, liveVerified=true, cleanup=confirmed-deleted. Сохранить только этот очищенный JSON с фактическими HTTP статусами. Подготовка script или прежние simulation tests не являются live evidence.

## Ошибка и очистка

При cleanup=UNCONFIRMED приёмка неуспешна, повторно запускать сценарий вслепую нельзя. Сохранить собственные slug/id из безопасного отчёта. В старой опубликованной админке вкладки блога нет, поэтому обычное удаление через blog UI пока недоступно: после восстановления обычного входа нужен ограниченный recovery transport в рамках уже разрешённой очистки в той же авторизованной console. Он должен GET /posts, подтвердить ровно собственные UUID/slug/title/draft и текущую revision, затем DELETE только этого id с revision и повторный GET. Нельзя подменять это удалением через SQL/секреты или удалять чужие записи. Существующий runner умеет recovering lost POST/PUT внутри того же запуска; новый random runId не очищает orphan предыдущего запуска.

## Границы результата

Этот runner проверяет live backend сохранение plain-text draft и revision/readback/cleanup. Он не проверяет rich editor le-richtext-v1, взаимодействия нового опубликованного UI или создание страниц storefront. Для этого нужен отдельно согласованный blog-only release и отдельный дальнейший QA. Реальный вход/HMAC/CORS и authenticated write остаются неподтверждёнными до выполнения вышеописанного уже разрешённого сценария. Следующий конкретный шаг — пользовательский обычный вход в указанной Pages-вкладке; publication нового UI для проверки backend не требуется.
